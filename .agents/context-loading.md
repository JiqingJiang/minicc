# 上下文加载规则

按[根协作规则](../AGENTS.md#接手任务)了解项目长期背景，再以用户在当前会话给出的目标和范围筛选相关上下文。

1. 从[架构](../docs/architecture.md)定位入口、模块和依赖。查相关目录规则、模块说明、已确认的 spec、代码和测试。以实际代码与验证证据核对当前行为。
2. 需要了解过去的选择时，先跟模块文档中的链接，再按功能名、模块路径、接口或用户原话搜 [Agent Notes](notes/README.md)。优先看当前提案和已落地记录。追溯旧方案时再查归档和否决记录。
3. 接续已有任务时，对齐当前用户要求、最近一次明确授权、已做的改动和验证版本。历史记录与现状不一致时，查后续决定和证据。只在缺失信息会影响本轮结果时向用户确认。

例如调查「切走后能否继续」时，先找 Runtime、HITL 和恢复边界，再按「重连」「后台」「续做」查相关说明和记录。结论要区分已确认的体验要求、代码现状和待验证事项。
