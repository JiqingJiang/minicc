# Agent Notes

这里保存会影响未来工作的决定依据和理由，包括重要取舍、仍有效的问题处置经验，以及值得跨会话复查的 Code Review 发现与修复结论。现行规则归对应协作规则；当前模块 spec 归 `docs/specs/<模块名>.md`；模块实际设计、实现逻辑、运行和验证方式归[模块文档](../../docs/architecture.md#模块文档)；协作流程文档归 `docs/workflow/`。

## 何时写

用户确认一项重要决定后，Agent 应主动检查是否需要记录，无需用户再次提出“记下来”。只有省略后可能导致未来 Agent 对范围、方案、接口、约束或验收作出不同判断时，才写 Note。

以下通常不写：日常问答、方向探索中的暂定想法、常规实现细节、常规进度、临时试错、未证实推测，以及已有权威文档覆盖的信息。若信息属于当前行为或验证事实，更新模块文档或 spec；Note 只保留未来选择方案时需要的原因、取舍、问题根因、处置和残余限制，不复制全文。

新建前先按主题、模块和用户原话搜索已有记录。优先补充或修订同主题 Note；仅在决定具有独立生命周期且没有合适的现有记录时新建。每次对话可以不产生 Note。

## 怎么写

使用[模板](_template.md)，保留未来决策真正需要的背景、决定、理由和证据。需要时补充备选方案、未决问题或重议条件。路径用 `<状态>/<类别>/YYYY-MM-DD-主题.md`。

| 状态 | 含义 |
| --- | --- |
| `proposed/` | 仍在讨论，或已确认但待实现或验证。 |
| `implemented/` | 已落地且经过验证。 |
| `archived/` | 暂存、过时或已被替代。 |
| `rejected/` | 已明确放弃。 |
