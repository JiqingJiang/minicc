# Agent Notes

记录值得后续继续讨论或复用的想法与取舍。每条记录回答想法是什么、为什么出现、考虑了哪些设计和参考资料、最后选择了什么、为此承担什么代价、为什么值得。模块运行方式和实现细节写入[模块文档](../../docs/modules/README.md)，在这里用链接带到对应位置。

## 记录与更新

- 用户提出实质性新想法，或讨论澄清了动机、选项、约束、证据或取舍时，就从[模板](_template.md)新建或更新对应 Note。保留仍在讨论的问题。会话里的普通问答、机械改动和重复内容可省略。
- 记录想法和正在形成的判断可随讨论进行。生成正式 spec、开始实现、Git 提交和推送各按当前授权执行。
- 同一主题优先更新已有 Note。引用实际参考过的资料、实验或项目，区分已观察到的事实与推测。决定变化时保留原理由和变化原因。已经落地的决定遇到实质变更时，另建 Note 并互相链接。
- 使用 `<状态>/<类别>/YYYY-MM-DD-主题.md`，日期为首次提出日期。类别可用 `feature`、`bug-fix`、`simplification`、`architecture`、`process` 或 `testing`。

## 跟进到结果

| 目录 | 状态与下一步 |
| --- | --- |
| `proposed/` | 新想法、讨论中、已定方案但仍待实现或验证。写下阶段、待确认项与下一步。 |
| `implemented/` | 想法已经执行并取得相应验证证据。链接模块文档、测试结果或对应版本。有改动影响事实时同步更新。 |
| `archived/` | 用户决定暂存、主题失去时效，或原决定被新决定替代。写明原因、日期和适用时的重启条件或替代记录。 |
| `rejected/` | 方案被明确放弃。保留否决理由及值得重议的条件。 |

移动 Note 时保留名称和历史理由，同步正文状态并修复链接。归档记录用于追溯。后来重启时在活跃目录新建记录并链接原件。每轮收尾时，按实际进度更新这轮涉及的 Note；未定或未完成的继续留在提案目录。
