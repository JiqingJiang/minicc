# Agent Note · 显式启动 Spec 和实现，提交后验收大模块

状态：archived

归档日期：2026-11-21

替代记录：[目标驱动的迭代流程](../../implemented/process/2026-11-21-goal-led-iteration.md)

## 问题

讨论可能跨多个会话，过早落 spec 或修改代码会把未定事项当成决定。大模块的测试需要对应可复查的 Git 版本。

## 决策

由用户分别触发 spec 和实现。大模块实现完成后由 Agent 提醒用户提交，确认提交号后先做功能正确性测试，再做深度测评。修复代码仍走显式实现入口。

## 备选与取舍

讨论结束自动出 spec 可减少一次交接，但会固化未完成的讨论。直接测工作区迭代快，但正式验收难与提交版本一一对应。选择用户控制启动时机，并用提交号对应测试证据。

## 影响

讨论可继续在会话中进行。现有 Sol 与 Luna 分工从获准实现后开始，提交后的评审仍由主 Agent 汇总结果。

## 验证

从根规则和使用示例核对触发条件，沿[开发流程](../../../skills/develop-change/SKILL.md)与[评审流程](../../../skills/review-change/SKILL.md)检查讨论、启动、提交提醒和两轮测评的顺序。
