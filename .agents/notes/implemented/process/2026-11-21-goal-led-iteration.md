# Agent Note · 从最终目标推进每轮迭代

状态：implemented

## 想法与来由

用户希望只需提供最终目标，Agent 每轮都据此推进工作，并追踪讨论中值得保留的想法。用户亲自体验可在正式测试前提供方向反馈，因此希望把它放在每轮交付的前面。

## 设计思考与参考

沿用此前 [MiniCC 的 Agent Notes 设计](2026-11-21-adopt-agent-notes.md)，把[最终目标](../../../../docs/project-goal.md)、[模块文档](../../../../docs/modules/README.md)和决策历史分开维护。原先的[显式启动和提交后验收流程](../../archived/process/2026-11-21-explicit-development-start.md)保留作历史参考。

## 选项、选择与取舍

以已提交版本验收，版本追踪简单，但会在用户体验和评测前固定迭代。新的流程先让用户体验，再做两轮验证，评测后由用户授权提交和推送。为避免版本混淆，测试前标识体验对应的版本或快照，提交前核对其与已验证内容的差异。

想法出现时直接记录来由和取舍。正式 spec 有独立触发点，获准实现后才更新相应模块的当前实现说明。这个布局允许长期保留讨论进展，并给用户控制正式文档、实现和版本保存的时机。

## 进度与证据

已更新[开发流程](../../../skills/develop-change/SKILL.md)和[验收流程](../../../skills/review-change/SKILL.md)。已检查文档入口、状态链接和迭代顺序。真实产品目标和模块版本将在用户提供目标后进入日常迭代。
