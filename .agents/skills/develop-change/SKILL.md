# MiniCC 开发流程

按[根协作规则](../../../AGENTS.md#授权与执行)和用户本轮明确授权判断阶段。用户的目标描述可能是初步想法；不要把探索自动升级成需求或实现。

## 1. 想法探索：判断值不值得做

用户提出未成形的方向时，先识别要解决的问题、场景、预期收益、已知证据、关键未知项和低成本验证方式。证据不足时比较继续探索、做小实验、暂缓或放弃的影响。把推断和事实分开。

此阶段不改产品代码、不写模块 spec，也不为每个想法创建文档。用户决定推进后再进入方案设计。不要为了减少打断而替用户作出是否值得做的实质决定。

## 2. 方案设计：先说明怎么做

读取[上下文加载规则](../../context-loading.md)，查相关规则、模块文档、代码、测试和历史决定。对涉及新模块、架构边界、重要依赖或用户可见行为的改动，调查可比方案，优先参考一手资料；说明方案在 MiniCC 中的适用性、成本、限制和证据。局部低风险改动可简化比较。

在进入实现前，向用户提供短小的实施说明，覆盖：

- 目标行为、范围和明确不做的事项。
- 用户可理解的核心逻辑、关键边界与失败行为。
- 主要模块或接口变化及其归属理由。
- 重要备选方案、选择理由、权衡和接受的限制。
- 预计涉及的主要路径和验证方式。
- 仍需用户决定的事项。

遇到会实质改变交付行为、公共接口、数据格式、安全边界、重要依赖或授权范围的选择时，带选项及影响请用户决定。范围内的常规实现细节由 Agent 处理。

### Spec 位置与授权

- 项目代码模块的当前 spec 放在 `docs/specs/<模块名>.md`，只在用户明确要求或同意写 spec 后写；同一模块持续更新现有 spec，不为每轮对话新建文件。
- 模块实际设计、实现逻辑、边界、运行方式和验证入口放在 `docs/modules/<模块名>.md`。经授权整理已完成模块文档时，使用[项目文档 Skill](../project-docs/SKILL.md)。
- 项目协作流程设计放在 `docs/workflow/`，不放在 `docs/modules/`。
- 写 spec 的授权不等于实现授权。进入代码、测试或配置修改仍须用户明确要求开始当前范围的实现。

## 3. 实现

获准后，核对范围、验收条件、工作区既有改动和相关验证入口。按现有模块边界实施，不静默改变已确认行为。

若实现中发现会改变目标行为、核心方案、接口、依赖或授权范围的新情况，暂停相关部分，解释影响并交用户决定。只在原授权范围内处理常规修正。

实现完成后，按[测试流程](../test-change/SKILL.md)确定并运行适用检查，再按[Code Review](../code-review/SKILL.md)独立审查本轮差异。两者结束后按本 Skill 的[用户验收与版本交付](#用户验收与版本交付)完成收尾。

## 4. 文档沉淀

关键决定经用户确认后，按[Agent Notes 规则](../../notes/README.md)主动记录，不需用户再单独要求。仅记录会影响未来范围、方案、接口、约束或验收的决定，以及需要跨会话复查的问题根因和修复结论。模块当前行为、设计、运行和验证方法更新到 `docs/modules/<模块名>.md`；模块 spec 更新到 `docs/specs/<模块名>.md`。

写入前先搜索已有权威来源并更新它。普通讨论、临时尝试、进度、未证实推测和其他文档已有的事实不另存。不要把流程规则写进代码模块文档。

## 5. 用户验收与版本交付

1. **用户体验。** 对照已确认的目标和验收条件，标明可复查的版本或工作区状态，提供启动入口、样例输入和体验重点。收到反馈后再继续；需要改变已确认行为时回到方案设计。
2. **功能验收。** 在用户体验的同一版本上，从真实入口验证主要行为、关键失败路径和受影响回归。记录实际操作、结果和未验证项。测试选择遵循[test-change](../test-change/SKILL.md)。
3. **深度评测。** 用代表性真实任务评估本轮关键目标，优先看完成率、产物质量和用户介入；涉及效率时再看响应、耗时和整项任务 Token。需要跨会话复查的证据写入对应模块文档。
4. **保存版本。** 验收后说明建议保存范围、验证状态和限制。提交与推送分别需要用户明确授权；提交前核对暂存内容，仅包含获准范围，保留无关改动。提交标题使用中文描述，可保留 `feat:`、`fix:`、`docs:` 等类型前缀，并对照近期历史格式。

## 6. 交付说明

交付时用普通语言说明实际行为和核心逻辑、主要取舍、改动位置、测试结果、Code Review 发现、未覆盖项及限制。让用户无需逐行阅读代码也能理解实现。说明事实、判断和未验证项之间的区别。
