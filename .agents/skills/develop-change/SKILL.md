# 开发流程

按[根协作规则](../../../AGENTS.md#授权与执行)判断本轮处于讨论、写 spec 还是实现阶段。

## 1. 讨论方案

1. 从用户在当前会话给出的目标出发，查相关规则、模块和实际实现。找出问题、出现条件和可用证据。本轮目标较宽泛时，提出一个用户可以亲自体验的切片。
2. 比较可行选项。用现有代码、同类实现、文档或实验解释每个选项怎样工作、成本是什么、在什么条件下值得采用。区分事实与尚待验证的假设。
3. 给出倾向方案和取舍。与用户对齐本轮要交付的行为、关键边界以及如何体验和验证。会改变交付的未决事项，带选项和影响请用户决定。讨论结论留在会话，用于后续确认。

## 2. 写 spec

获得写 spec 的授权后，在 `docs/modules/<模块名>/spec.md` 写清范围、主要行为、相关接口与约束、用户体验步骤和验收方式。标出未决定的问题。评测涉及质量或效率对照时，写明场景、证据和度量口径。

## 3. 实现

1. 获得实现授权后，核对本轮范围、工作区已有改动和验收条件。先找现有的入口和同类实现，沿既有模块边界改动。
2. 独立、可验收的部分按[模型分工](../model-routing.md)处理。主 Agent 负责跨模块取舍、整合与复核。涉及已确认行为或范围的实质变化时，回到讨论。
3. 完成后核对改动范围和实际差异。模块入口、用法或验证方式有变化时，同步到[模块文档](../../../docs/architecture.md#模块文档)。产品实现再进入[验收流程](../review-change/SKILL.md)。
