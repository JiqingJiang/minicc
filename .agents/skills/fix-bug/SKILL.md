# Bug 修复

用于用户明确要求修复缺陷，或已授权实现的缺陷修复任务。初步报告、怀疑或评审发现本身不等于修改授权；按项目根规则确认本轮授权范围。

## 工作方式

1. 读项目目标、架构、上下文加载规则和相关模块说明。核对提交基线、工作区差异与调用路径，保留已有未提交内容。
2. 把报告拆成可观察的触发条件、实际结果和预期结果。沿代码找到根因；区分已证实事实与推断。若无法复现，继续查证并说明证据缺口，不把猜测当作原因。
3. 在适合的测试层添加最小回归用例，验证旧实现会失败。若无法安全或合理地先测，说明原因，再采用其他可靠验证方式。
4. 修改根因所在边界，优先做窄修复。避免顺带重构或改变无关行为。若修复需要改变已确认行为、接口、安全边界、依赖或授权范围，先按开发流程交用户决定。
5. 执行针对性回归和受影响范围内的测试，再独立检查本轮差异。按[test-change](../test-change/SKILL.md)和[Code Review](../code-review/SKILL.md)报告实际命令、结果、未覆盖项和残余风险。

## 验收

- 回归用例能稳定触发原缺陷条件，并在修复后验证预期行为。
- 修复没有破坏相邻行为；范围外改动保持原样。
- 说明改动位置、根因、测试证据、Review 发现和仍未知的情况。
