# 验收与版本交付

## 1. 用户先体验

对照已确认的目标和验收条件复核改动。标明体验对应的提交号或可复查的工作区状态，提供启动入口、样例输入和体验重点。收到用户体验反馈后进入功能验证。需要改变已确认行为时，回到[开发流程](../develop-change/SKILL.md)。

## 2. Agent 做功能测试

在用户体验的同一版本上验证。按改动选最相关的检查，从正常入口覆盖主要行为、关键失败路径和受影响的回归。记录实际执行的命令或操作、结果和未验证项。版本有实质变化时，重新核对体验和验证范围。

## 3. 深度评测

用代表性的真实任务验证本轮最关键的问题。优先看完成率、产物质量和用户介入次数，涉及效率时再看响应、耗时或整项任务 Token。记录场景、版本、环境、口径和可用基线。需要跨会话复查的证据放到[对应模块](../../../docs/architecture.md#模块文档)。

## 4. 保存版本

验收后说明建议保存的范围、验证状态和仍有限制的项目。按[根规则](../../../AGENTS.md#验收与版本)确认提交和推送各自的授权。提交前核对待提交差异与验证范围，保留无关改动。提交信息用 `<英文类型>: <中文摘要>`，例如 `fix: 恢复待确认的任务`。推送后核对远端目标，汇报提交号和分支。
