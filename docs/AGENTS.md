# AGENTS.md — 文档规范

本文件定义 minicc 的文档结构、内容归属、写作规则、字数边界和交叉引用方式。

普通项目文档放在 `docs/`，用户入口文档为根目录 `README.md`。设计决策、取舍、风险和验证记录放在 `.agents/notes/`，并遵循该目录下的 `README.md` 与 `AGENTS.md`。

## 文档结构

- 文档范围由主题和路径共同决定；不要因为内容相关就把不同职责混在同一个文件中。
- 教程说明“如何完成一件事”；参考文档说明“系统当前是什么”；决策 Note 说明“为什么这样设计”。
- 新增内容前先判断它属于哪个权威文档；已有事实应修改原归属位置，而不是复制到新文件。
- 文档描述当前有效状态。历史变化、被否决的方案和设计过程放入 `.agents/notes/`。

## 文档层级：每个事实只有一个归属位置

| 层级 | 职责 | 不应包含 |
| --- | --- | --- |
| 根目录 `AGENTS.md` | 全局开发约束和每次任务都必须遵守的规则 | 详细架构、教程、决策历史、重复规则 |
| `docs/AGENTS.md` | 文档结构、内容归属、写作和引用规则 | 全局开发规则、具体功能设计、历史记录 |
| `commit-convention.md` | Git 提交信息格式、提交拆分和提交前检查 | 代码架构、功能实现、完整开发过程 |
| `architecture.md` | 当前系统组成、模块关系、核心流程和扩展边界 | 单个函数实现细节、逐行代码、决策理由 |
| `subsystems/*.md` | 各个具体子模块的职责、接口、数据流、约束和测试说明 | 全局架构、其他子模块的重复说明、完整实现代码 |
| 根目录 `README.md` | 面向用户的项目介绍、安装和快速开始 | 内部决策、开发过程、详细实现说明 |
| `.agents/notes/` | 设计理由、备选方案、后果、风险和验证结果 | 普通教程、当前架构全文、完整聊天记录 |
| `.agents/skills/` | 可复用的 Agent 工作流和专项规则 | 运行时接口、当前实现状态、一次性任务记录 |

## 内容放置原则

```text
全局开发约束 → 根目录 AGENTS.md
文档写作约束 → docs/AGENTS.md
Git 提交规范 → commit-convention.md
系统结构和模块关系 → architecture.md
具体子模块文档 → subsystems/
用户使用说明 → README.md
设计理由和取舍 → .agents/notes/
可复用工作流 → .agents/skills/
```

- Bug 或事故的原因、影响和修复取舍写入对应 Note；可复用的预防规则再补充到规范文档。
- 每个具体子模块的文档放在 `docs/subsystems/` 下，并使用能够表达模块职责的文件名，例如 `agent.md`、`memory.md` 或 `model-provider.md`。
- 子模块文档只描述本模块的职责、边界、接口、关键数据流、依赖关系和测试要求；跨模块关系回到 `architecture.md`。
- 代码模块放在 `packages/<模块>/` 下；模块源码放在该模块的 `src/`，模块测试放在该模块的 `tests/`，不在仓库根目录集中放置模块测试。
- 架构文档只描述当前事实，不承担测试记录、实现过程或未来计划。

## 写作规则

- 描述当前有效状态，不把历史过程写成当前规则。
- 每个事实只保留一个权威来源，其他位置使用链接引用。
- 使用直接、具体、可执行的表达；命令、路径、配置项和接口名称必须准确。
- 不记录完整聊天过程、未经筛选的推理、显而易见的代码或逐行测试过程。
- 行为、接口、配置或测试方式发生变化时，同步更新对应文档。
- 重要设计理由、备选方案和风险写入 `.agents/notes/`，不要塞入普通说明文档。
- 已实现文档使用确定语气；未完成计划应写入 `proposed` Note，不要伪装成现状。
- 教程按目标和步骤组织；参考文档按主题组织，方便检索；段落保持短小。

## 字数上限

字数上限是防止文档膨胀的护栏。超过上限时，先拆分到正确归属文件、删除重复内容并压缩表达；确需提高上限时，先记录一份 Note 说明原因。

| 文件 | 建议上限 |
| --- | ---: |
| 根目录 `AGENTS.md` | 600 字 |
| `docs/AGENTS.md` | 1200 字 |
| `architecture.md` | 1800 字 |
| 单个 `subsystems/*.md` | 1200 字 |
| 根目录 `README.md` | 1000 字 |

## 内容冗余检查清单

- [ ] 同一条规则是否出现在多个文件中？
- [ ] 是否把历史过程写成了当前状态？
- [ ] 是否把实现细节或未来计划写进了架构文档？
- [ ] 是否手工重复了代码、配置或脚本中的权威内容？
- [ ] 是否把设计理由、测试过程或评审过程写进了不恰当的文档？
- [ ] 相邻文档是否重复解释同一个背景或结论？
- [ ] 是否存在过长段落、空泛表述或重复强调？
- [ ] 已完成的 Note 是否仍保留提案语气？
- [ ] 文件移动、删除或重命名后，交叉引用是否仍然有效？

## 使用机器可检查的交叉引用，不使用自由文本

引用其他文档时使用相对路径的 Markdown 链接：

```markdown
[Agent Notes](../.agents/notes/README.md)
```

不要只写“见相关文档”。链接必须指向真实存在的文件；使用标题锚点时，必须使用真实存在的 `#fragment`。后续可以通过脚本检查链接目标和文档字数。
