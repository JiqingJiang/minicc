# MiniCC 架构与代码目录

首个任务切片确定语言、界面形态、通信方式和存储实现。产品范围与验收见[项目目标](goal.md)。

## 运行结构

采用本地运行时，界面可独立连接。界面提交消息、订阅进度、展示提问和产物。运行时关联会话与任务，管理执行、取消、人工等待、恢复和完成，并维护任务的权威状态。

任务运行时驱动 Agent Loop。每轮由 Context 选择目标、规则、历史、偏好、Skill、工具描述和必要的执行结果，经模型适配层调用模型。Loop 根据回复执行工具、提出问题、继续迭代或交付结果。运行时保存用户决定、工具结果及产物引用，并按任务关联模型调用与验证证据。

## 实现边界

- **依赖方向。** Client 通过运行时契约读状态和提交请求。Runtime 驱动 Harness；Harness 接受数据视图和能力接口，返回执行结果。接口定义靠近使用方，具体适配器由 App 注入。
- **状态与上下文。** 会话保存历史，任务保存已确认的目标、可调整的计划及执行进度，Memory 保存可纠正的跨聊偏好。Context 为当次请求选材，按需引用原始日志和产物。当前任务的明确要求可以覆盖偏好。
- **人工交接与工具。** HITL 按任务和请求记录问题、决定及恢复位置。需求澄清更新任务要求，工具批准绑定操作和授权范围。内置工具和 MCP 工具经过同一权限入口，Sandbox 落实本地执行限制，远端操作受对应服务的身份与权限限制。
- **恢复。** 界面重连时获取任务快照及后续更新，恢复待答事项与结果。先验证运行时存活时的重连。运行时退出后的自动续做单独设计，结果未知的外部操作先核对再决定如何继续。
- **观测。** 记录每次模型请求的用量和上下文来源，关联重试、压缩、等待及子任务。按整项任务汇总 Token，缓存用量单列。Tests 验证行为，Evals 比较交付质量、用量、耗时和用户介入。

## 实施顺序

首个切片用单 Agent、一个模型适配、最小状态持久化和受限工作区工具完成一项真实仓库改动。验收关键选择能询问、切走后能继续、交付可验证，再用短任务检查响应。Memory、Skill、MCP、Hooks、SubAgent 和 Team 由真实场景拉动实现。复用模型适配或 Loop 时，保留对上下文装配、逐次用量和人工等待的控制。
