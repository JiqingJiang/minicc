# 提交规范

本文件定义 minicc 的 Git 提交信息和提交前检查要求。

## 提交信息

- 提交信息必须使用中文。
- 一次提交只表达一个完整、可说明的变更。
- 首行使用格式：`类型：简短说明`。
- 简短说明使用动词开头，不超过 50 个汉字，不以句号结尾。
- 可用类型：`新增`、`修复`、`文档`、`重构`、`测试`、`维护`。
- 需要补充背景时，在首行后空一行，再写简短正文；正文说明原因、影响或验证结果，不复制聊天记录。

示例：

```text
文档：建立模块化代码目录规范
新增：创建 core 模块基础目录
修复：拒绝未配置的模型名称
```

## 提交前检查

- 只暂存当前任务相关的文件。
- 检查 `git diff --cached`，确认没有密钥、个人配置、生成文件或无关修改。
- 运行当前任务对应的最小测试或验证命令。
- 测试未通过、验证未完成或变更范围不清晰时，不提交。
- 提交后使用 `git show --stat --oneline HEAD` 检查提交结果。

## 提交拆分

- 文档、目录调整、功能实现和测试更新如果可以独立理解，应分别提交。
- 不为了凑提交数量拆分强耦合变更。
- 不使用含糊的提交信息，例如“修改一下”“临时更新”或“杂项”。
