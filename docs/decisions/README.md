# 项目决策记录

这里保存具体决定会影响 MiniCC 后续范围、方案、接口、约束或验收的原因与取舍，以及值得复查的问题根因和修复结论。持续有效的行为规范放在[项目规则](../rules/README.md)，不要把规则副本放进决策记录。`docs/specs/` 保存已确认的模块要求，`docs/modules/` 保存当前实现事实。

## 何时记录

用户确认重要决定后，检查省略其理由是否会使未来的实现或验收出现不同判断。只有答案为“会”时，才新建或更新记录。日常进度、临时尝试、未证实推测和已由权威文档完整覆盖的事实不另记。

优先更新同主题记录；按需要在 `proposed/`、`implemented/`、`archived/`、`rejected/` 下组织。每篇记录使用[模板](_template.md)，包含背景、决定与理由、证据和后续条件。模块 spec、实现说明和决策记录之间应互相链接。
