# 决策记录 · Memory 与 Context 首版存储

状态：implemented

## 背景

Memory 与 Context spec 将存储、检索和预算留给实现阶段决定。当前 Runtime 只有进程内聊天历史，没有数据库或任务存储。数据布局和项目身份会影响后续迁移与记忆隔离。实际实现见[模块说明](../../../../docs/modules/memory-context.md)，行为要求见[spec](../../../../docs/specs/memory-context.md)。

## 决定与理由

- 用标准库 JSON 文件保存 Memory、任务状态和原始会话记录，放在用户私有状态目录，不写进项目仓库。这样首版无需引入数据库依赖，也避免偏好和聊天记录跟随项目提交。
- 全局 Memory 单独存放；项目身份使用 Git 根目录规范化绝对路径的 SHA-256。非 Git 工作区使用工作区绝对路径。相同目录名不会共享数据；移动仓库视为新项目，避免无提示地把旧项目记忆带入另一个位置。
- Memory 写入与检索分别暴露为 `memory_remember` 和 `memory_search` 工具；Context 还会在每次请求前按当前请求/任务状态自动召回少量候选。候选使用 BM25、jieba 中文搜索分词和本地 FastEmbed 语义向量混合排序。向量模型采用 `BAAI/bge-small-zh-v1.5`，首次使用下载后在本机 CPU 推理，不向第三方发送记忆文本；模型关闭或推理失败时退回 BM25。
- JSON 记录保留来源、有效时间、历史版本和关系边。精确重复合并来源；补充独立关联；用户纠正/确认取代旧记录；时间更新保留旧记录但不默认检索；冲突/不确定分组并在召回时一并返回。用户可查看、编辑、解决冲突和删除。
- 历史压缩仅生成有界请求摘要，原始消息仍完整保存；这样摘要错误不会改写历史依据。Context trace 记录来源、估算与适配器返回用量。
