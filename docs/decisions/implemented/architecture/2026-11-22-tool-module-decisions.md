# 决策记录 · Tool 模块设计与评审处置

状态：implemented

## 背景与要保留的信息

Tool 模块的实现跨工具定义、执行、Agent Loop、Session 审批交接和工作区文件边界。以后扩展内置/MCP 工具、改变授权或调整模块文档时，需要保留这些决策来由和代码评审发现；当前行为、接口与验证入口集中在[模块说明](../../../../docs/modules/tools.md)，已确认行为要求在[当前 Spec](../../../../docs/specs/tools.md)。模块文档的职责边界见[文档归属规则](../../../../docs/rules/documentation.md)。

## 决定与理由

- **统一执行边界。** Registry 只维持注册顺序和查找；Executor 在提供给模型及实际执行时验证定义/参数，并统一预算、审批、结果和异常。这避免搜索出的能力与可执行集合不一致，也让坏工具定义不会影响无关工具。
- **审批按副作用能力划分。** 读、搜索和发现不逐次审批；文件写入/编辑和每条 Bash 命令需用户批准。Bash 仍在当前用户权限下运行，审批不是沙箱；未来接入不可信命令或扩展工具前须先提供隔离边界。
- **工作区文件使用独立权限模块。** 采用相对路径、目录文件描述符、拒绝符号链接/敏感路径和有界读取。写入先展示基线差异，再通过平台原子交换核对目录项的并发变化；不支持交换的文件系统上安全失败。若回滚失败，保留临时副本并报告路径。此措施不锁定已经打开旧 inode 的非协作写进程；若要支持任意外部并发写入，需另外设计系统级协调或隔离。
- **正则搜索限时。** Python 标准 `re` 对单次 `search` 无法应用 Loop 检查点，灾难性回溯会卡住调用。因此 `grep` 使用有匹配超时的 `regex` 依赖，单行最多 50 毫秒。
- **保留的 Review 边界。** 早期 Review 还发现工具截止时间依赖工具定期调用 `checkpoint()`；通用 Python 工具不能被执行器安全强杀。新增长操作必须配合检查点，若需硬中止则应在后续隔离进程方案内实现。

## 评审问题与证据

最近的 Code Review 发现原 `os.replace` 前的基线复核存在 TOCTOU 竞态；最终采用原子交换后核验被替换项，并测试交换前并发修改、回滚失败以及回滚期间再次修改。Review 另发现标准库正则的单次匹配不受协作式截止时间控制；修复后用灾难性回溯输入验证 `REGEX_TIMEOUT`。

此前检查的其他执行边界问题包括 Schema 预算内工具筛选、严格 JSON 去重规则、Schema `format` 校验和按 UTF-8 字节限制预览；这些规则由 Executor 收口，并有定向回归用例。

2026-11-22 的 `.venv/bin/python -B -m unittest discover -s tests -v` 有 29 项通过；技能整理时未运行真实模型评测，用户体验验收仍待完成。此前历史评测中的供应商 HTTP 500 不可作为当前实现的成功/失败样本，恢复服务后应重新获取可评分轨迹。
