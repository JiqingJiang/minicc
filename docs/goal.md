# MiniCC 项目目标

## 目标

做一个通用 Agent Harness 客户端。参考 Codex、Claude Code、DeepSeek Harness 和 Pi，逐步达到同等的任务覆盖和交付质量，并显著降低完成整项任务的总 Token。

长期接入企业业务流程。企业提供目标、规则和推进条件，MiniCC 执行任务，在需要人决定时交回控制权，并交付可核查的结果。

## 当前范围

先用学校和个人项目里的真实任务验证，以 Codex 为主要对照。

- **编码和项目。** 了解已有项目，讨论方案，在任务明确后修改并验证。
- **润色和整理。** 保留原意，整理草稿和讨论。用户明确要求时才沉淀成笔记。
- **调研和演示。** 查资料、给出可核对的来源，按要求交付可直接打开的 HTML 演示稿。
- **聊天和学习。** 延续多轮讨论，遇到理解障碍可以换一种方式讲解，按要求总结。

企业系统集成、复杂办公任务和浏览器操作留到后续阶段。

## 使用体验与验收

- 重开旧聊天能接上已确认的决定、已做的工作和待解决的问题。新聊天能用上相关偏好，用户可以纠正或在当次覆盖。
- 任务明确时自主推进。关键信息会改变交付时，用带选项和自填项的确认框询问，回答后从已有进度继续。
- 短任务响应快，产物可直接使用。用户切走后长任务继续推进，回来能看到结果、进度或待处理的问题。
- 用真实任务先比完成率、产物质量和用户介入次数，再比响应时间和整项任务的总 Token。优先固定模型和任务条件，统计覆盖多轮、重试、后台执行和续做。具体门槛由首批实测确定。
