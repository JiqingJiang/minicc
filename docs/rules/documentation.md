# 文档归属与整理规则

- `docs/specs/<模块名>.md` 保存用户确认的当前模块要求和验收条件。用户明确要求或同意写 spec 后才创建或修改；同一模块持续更新已有 spec。
- `docs/modules/<模块名>.md` 保存当前实现的结构、设计逻辑、边界、运行方式、验证入口和已知限制。以代码和实际验证为依据，不从实现反推用户要求。
- `docs/decisions/<状态>/<类别>/YYYY-MM-DD-主题.md` 保存会影响未来范围、方案、接口、约束或验收的原因与取舍，以及需要复查的问题根因和处理结论。
- `docs/rules/` 保存持续有效的项目规范。规范适用范围和执行方式应清楚；不要把它误写成一次性方案决策。
- `docs/workflow/` 保存协作流程和 Codex 设置说明。
- 保持每项信息只有一个权威来源，其他文档通过链接引用。修改文档归属时，全文搜索并更新引用，检查本地链接。
