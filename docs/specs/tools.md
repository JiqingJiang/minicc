# MiniCC 工具模块 Spec

状态：当前已确认范围；实现已完成定向离线测试，用户体验和真实任务评测待验收。

模块实现和验证证据见[工具模块说明](../modules/tools.md)。重要设计理由和问题处置见[项目决策记录](../decisions/implemented/architecture/2026-11-22-tool-module-decisions.md)。

## 目标与范围

让 Agent 在用户明确工作区内通过受控工具完成文件阅读、查找、修改与必要命令操作。模型只可调用当前请求实际提供的工具；调用需要经过定义/参数校验、预算和权限流程，并以对应调用 ID 收到结果。

当前默认提供 `read`、`write`、`edit`、`tool_search`、`bash`、`glob` 和 `grep`。本 Spec 不定义 MCP 接入、跨进程任务恢复、OS 级 Bash 沙箱或通用插件发现。

## 预期行为

- `read`、`glob`、`grep` 只访问工作区相对路径下受允许的普通文件；读取和扫描必须有大小、条目或结果限制。
- `write`、`edit` 必须在副作用发生前展示操作预览并得到本次明确批准。用户拒绝、基线改变或无法安全完成时，不应静默覆盖；无法安全恢复时应保留可恢复副本并报告。
- 每条 `bash` 命令都展示完整命令和工作目录，并单独审批。批准不会改变命令的 OS 权限范围；当前实现的限制必须向用户明示。
- 工具定义和输入在执行边界校验；错误和结果关联原始 `call_id`。工具错误、请求重试、拒绝和中止不得导致已成功副作用被静默重放。
- Agent Loop 对模型请求、工具尝试和执行时长设限；耗时操作应响应截止检查。无法安全强制停止的执行能力必须明示其限制。

## 当前工具契约

| 工具 | Spec 行为 | 审批 |
| --- | --- | --- |
| `read` | 有界读取工作区 UTF-8 文本和行范围。 | 否 |
| `write` | 创建或完整更新文件，展示差异并在批准后写入。 | 每次 |
| `edit` | 仅替换唯一匹配文本，展示差异并在批准后写入。 | 每次 |
| `tool_search` | 只发现当前有效且可提供给模型的工具。 | 否 |
| `bash` | 在展示工作目录中执行命令，每条命令单独批准；不宣称 OS 隔离。 | 每条命令 |
| `glob` | 按工作区相对模式列出有界文件名。 | 否 |
| `grep` | 按正则搜索工作区文本，单次匹配必须可限时。 | 否 |

## 验收

- 对正常调用、非法 Schema/参数、未知工具、预算耗尽和模型请求重试做离线回归。
- 验证拒绝时没有文件/命令副作用；审批预览与实际操作对应；检测到的目录项并发修改会安全回滚或保留冲突副本。
- 验证工作区越界、敏感路径、符号链接、大小/扫描上限和搜索超时受到约束。
- 从终端入口体验工具选择、审批、拒绝、重试和取消；真实任务评测报告完成结果、审批、重试、工具错误、耗时和 Token。
